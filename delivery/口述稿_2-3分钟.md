# 2–3 分钟中文口述稿（用于向教授汇报）

各位老师好，我这次做的是论文《Rethinking Molecular Text Representations for LLMs: An
Empirical Study》的复现。先说研究问题：同一个分子可以写成很多种"文本形式"——SMILES、
SELFIES、IUPAC 名称、CML、InChI 等。这篇论文想验证的是：**固定题目、只改变"写法"，
大模型的回答会不会变、差别有多大。**它不是训练新的分子模型，而是把已有的开源化学模型
当受试者，用 9 种表示、8 类任务系统测量。

我这次做了什么，分三块。

**第一块：把环境与数据链路完整跑通并核验。**我建了独立的 Python 3.12 环境，验证了作者
公开代码的 32 个文件 SHA256 一个都没改，11 个单元测试全部通过。然后我重新生成了两份题目
计划：smoke 是 270 条（8 类任务 × 9 种表示，每个格子 2 个分子），paper 是 29139 条。关键一点：
我生成的 manifest 哈希和交付环境记录的完全一致，说明数据链路是对的。

**第二块：我发现并处理了数据本身的问题。**我用 OPSIN（一个公开的名称解析服务，不是大模型）
把 4551 个分子的公开 IUPAC 名称逐个解析回结构，结果只有 2697 个（约 59%）和原分子在立体
化学上完全一致，287 个根本解析不出来。也就是说，论文公开的 IUPAC 那一列本身就存在信息丢失
和错误映射。所以我又生成了一条"已审核路线"（27654 条），只保留名称经得起验证的输入。

**第三块：我用真实的模型跑了实验。**用 DeepSeek 官方 API 的 deepseek-flash，关闭推理，
在 smoke 的 270 条上全部成功返回。我核查过原始返回是真实模型回答，不是占位样本——
有真实 token 用量、有 finish_reason。第一条真实链路是：给模型一个 AMP 分子的规范 SMILES，
问它里面有 13 个碳原子，模型回答 13，RDKit 算出的标准答案也是 13。

结果上，我看到两个很清楚的现象。第一，**表示越长越吃亏**：同样是数原子，canonical SMILES
（平均 70 个字符）基本都能答对，而 SELFIES 直接 0/2；CML 和 MolJSON 的平均长度是
SMILES 的 40 到 60 倍，生成任务里经常被截断——本次有 3 条回答用满了 8192 token 被切断。
第二，**逆向生成任务上，validity 高不等于答对**：canonical SMILES 生成出来的分子
validity 是 100%，但 exact match 只有 50%，也就是说模型给出的分子是合法的、却不是题目要的那个。

必须说清楚这次的范围和局限。第一，论文用了 15 个开源模型，我因为预算只跑了 1 个商业 API
模型，而且这个模型不在论文的列表里，所以这是**部分复现**，不能说是复现了论文的哪一行结论。
第二，smoke 每个格子只有 2 个分子，样本太小，配对 bootstrap 因此拒绝给出置信区间
（程序要求至少 3 个可配对分子），我没有为了"有数"去放宽阈值。第三，FCD 指标、论文的
LLM 裁判图、以及第 6 节的机制分析，这次都没有跑，我在报告里明确列为未完成。

我下一步会做的是：把 smoke 换成 paper 级规模，让每个格子有 200 个分子，这样才能算出
置信区间，也才有资格说"哪种表示更好"。

以上是我的复现情况，请老师指正。

## 如果被追问"哪个表示最好"，这样回答

不要下"哪个最好"的结论。本次每个格子只有 2 个分子，差异完全可能是随机波动。
可以说：**在本次的小规模实验中，短的、非冗余的表示（canonical/isomeric SMILES）
在计数与选择类任务上表现较稳，而 CML、MolJSON、SELFIES 这些更长或语法更特殊的表示
更容易出现截断或无效输出；但要下结论必须先跑 paper 级规模并给出置信区间。**
