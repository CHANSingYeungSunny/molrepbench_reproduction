# 教授可能追问的问题与基于本次证据的回答

每条回答都指向本次实际产生的文件，避免"凭印象回答"。

---

### 1. 你跑的到底是论文的实验吗？

论文用了 15 个开源模型（Qwen3 系列、Phi-4、OLMo-3.1、ChemDFM 等）。本次用的是 DeepSeek
官方 API 的 `deepseek-flash`，**不在论文模型列表中**，规模只有 smoke 的 270 条
（论文 paper 档是 29139 条）。所以严格说这是 **partial reproduction**：
我验证了整条流水线与数据，而不是复现论文的某一行结论。
证据：`evidence/settings_decisions.md`、`results/deepseek-flash_off_smoke_run3/run_metadata.json`。

### 2. 你怎么证明模型真的回答了，而不是程序造的数据？

三条证据链：
1. `raw.jsonl` 里保存了服务端返回的原始文本、`usage`（token 用量）、`finish_reason`、
   `served_model`；
2. 探测请求返回了 `system_fingerprint` 与 `usage.prompt_tokens=13, completion_tokens=2`；
3. 我用一条已知答案的题做了端到端校验（见报告"每类任务一条真实链路"）。
另外 `evaluation_status.json` 里 `result_kind = real_model_inference`。
在最初两次尝试中，API 返回 401（密钥无效），运行器**按设计直接中止**并把失败记录留在
`results/deepseek-flash_off_smoke/`，我没有把失败项删掉或改成成功。

### 3. 为什么不用论文的 15 个模型？

预算与显卡限制：本机是 4GB 显存的 GTX 1650，无法本地部署 4B 以上的模型；
论文的多个模型超过 100B，远超本地能力，且我没有自行创建付费账户或下载数十 GB 权重的授权。

### 4. 每个格子只有 2 个分子，结论可信吗？

**不可信**，我在报告和口述稿里都明确写了。smoke profile 的作用是验证流水线和覆盖率，
不是给出科学结论。要回答"哪种表示更好"，需要 paper 级（每任务 200 分子）并给出置信区间。

### 5. 你的置信区间呢？

本次 `paired_bootstrap.json` 是空的（`comparisons = 0`）。原因是实现要求每个"任务×表示"
至少有 3 个可配对分子（`repro/scoring.py` 中 `len(ids) < 3` 即跳过），而 smoke 每任务只有 2 个。
我没有把阈值改成 2 去凑出数字——2 个配对单位算出的 CI 没有统计意义。
另外要注意：本次 bootstrap 是**以 canonical_smiles 为预指定参考**的配对比较，
论文是"先选最高均值再比较"，两者细节不同，我已在报告中记录这一差异。

### 6. 你发现数据有什么问题？

两个具体发现：
1. **IUPAC 名称列不可靠**：4551 个成员经 OPSIN 解析，只有 2697 个（59%）与成员 SMILES
   立体身份完全一致，41 个仅连接性一致，1567 个不一致，287 个无法解析。
   证据：`evidence/iupac_input_audit.json`。
2. **B9 有 4 对标签在当前 RDKit 下有争议**（分子对 34、62、102、115）。
   我保留了公开标签，并做了敏感性检查：把互变异构体枚举上限从默认提到 10000，
   这 4 对**仍然不一致**，说明不是枚举上限造成的，成因需要向作者澄清
   （版本或标准化规则差异）。证据：`evidence/b9_label_sensitivity.json`。

### 7. SELFIES 的 validity=0 是模型幻觉吗？

要分两步看。SELFIES 的特点是**语法上任何字符串都是合法分子**，所以"能否解码"不能证明答案对。
本次 B6 生成任务中 SELFIES 出现了 `finish_reason=length`（用满 8192 token 仍在重复
`[C@H1]` 片段），这类输出既超长又无法解码成目标分子，是真实的模型失败模式，
我按原样记录，没有静默丢弃。论文中 SELFIES 的正确率也异常低，原因之一可能正是这种重复退化。

### 8. validity=100% 是不是就答对了？

不是。本次 canonical SMILES 生成任务的 validity 是 100%，但 exact match 只有 50%，
Tanimoto 相似度也远低于 1。这说明模型能产出合法分子，但不是题目描述的那个分子。
所以 B6 必须同时报告 validity、exact match 和 Tanimoto，我在报告里三者都列了。

### 9. 你在 Windows 上遇到什么问题？怎么保证不是"假 CML"？

Windows 版 `openbabel-wheel` **完全不支持 CML 格式**（输入输出都没有），conda-forge 的
3.2.1 也移除了 CML。我定位到 3.1.1 的 obabel CLI 仍带 CML，并且**作者的
`cml_to_smiles` 本身就是 shell out 到 obabel CLI**，所以我按作者同款方式做了平台适配。
关键点：适配只发生在**表示字符串的生成与解码**环节，prompt 里的 CML 是真实 XML，
我验证过 CML 往返保留立体与电荷，**没有任何地方用 SMILES 冒充 CML**。
证据：`evidence/doctor_output.json`（obabel 路径）、`evidence/ARTIFACT_INDEX.md`。

### 10. B5 的标签你用的是哪个版本？

用 CSV 里的 `ground_truth`（250 个 Yes，125 个 stereoisomer 为 No，125 个 substitution 为 No）。
作者原始 evaluator 的 natural/stereoisomer 规则在 375/500 对上与 CSV 不一致，
这是代码与数据的矛盾，我以公开 CSV 为准，**没有恢复那个错误规则**。

### 11. 你算 FCD 了吗？

没有。FCD 需要可选依赖 `fcd` 和 ChemNet 预训练权重，本次未安装、未运行，
报告里明确列为未完成，也没有用别的距离指标冒充 FCD。

### 12. 论文的 LLM 裁判和机制分析呢？

都没有跑，而且要说清原因：
- 裁判需要 `GEMINI_API_KEY` 和 14 个模型的 B6 回答，我都没有；
  我审读了 `vendor/molrepbench/scripts/qualitative_eval.py`，确认原裁判是
  Gemini 3 Flash、每分子 10 个样本、14 个模型批处理、3 个 1–5 分维度 + 错误类型枚举，
  本项目的 `judge` 是**改编版**，不能声称与原裁判逐字一致；
- §6 的线性探针/注意力重放在公开的 32 个文件里**没有**可完整重放的实现，
  需要向作者澄清模型、采样、层选择、池化方式等细节，我不会猜着实现再声称是论文原方法。
证据：`evidence/review_vendor_boundaries.md`。

### 13. 你改过作者代码吗？

没有。`reproduce.py verify-vendor` 校验 32/32 文件 SHA256 全部一致。
我的改动都在 `repro/` 和 `tools/`：
- `repro/core.py`：Windows CML 的 obabel CLI 平台适配；
- `repro/scoring.py`：把状态文件里那句固定说明改为读取 `run_metadata.result_kind`；
- `tools/`：密钥隐藏输入启动器、OPSIN 并行预取、连通性/密钥诊断、完整报告生成器。
`tests/test_pipeline.py` 有一处断言改为与 OPSIN 缓存状态无关（原断言假定没有缓存）。

### 14. 密钥安全吗？

密钥只放在项目根的 `.env`（已在 `.gitignore` 中），由 `tools/run_with_key.py`
通过 `getpass` 或读取 `.env` 注入子进程环境变量，**不写入 settings.json、结果文件、
日志、报告或 Git**。诊断工具只输出长度、字符类型和哈希指纹，不回显密钥内容。
另外提醒：该密钥曾在聊天中出现过，建议在 DeepSeek 控制台轮换后再长期使用。

### 15. 下一步怎么做才能下科学结论？

1) 跑 paper 级计划（29139 条）或多任务 × 200 分子的中等规模，让每格至少 3 个配对分子；
2) 优先跑"已审核 IUPAC 路线"，避免把名称错误算成模型能力；
3) 报告 validity + exact match + Tanimoto + Spearman，并给出配对 bootstrap 的 95% CI；
4) 明确区分"表示差异"与"预算截断"，对 finish_reason=length 的样本单独统计；
5) 若需要与论文直接对比，再申请 GPU 资源跑论文中的开源模型。
